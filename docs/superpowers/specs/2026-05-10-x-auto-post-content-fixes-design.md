# X自動投稿 内容整理 設計書（事故修正4点）

- 作成日: 2026-05-10
- 対象: `@ORI2024202463`（ORI MAMA / 矢萩香織）の自動投稿
- 目的: 直近観測された投稿事故を、プロンプト改修と生成後フィルタで止血する
- 範囲: プロンプト・生成・選定ロジックの修正のみ（カテゴリ再設計や冷頭フック多様化は対象外＝別件）

## 1. 背景・問題

GitHub Actions で朝8時／夜21時に自動投稿している現行運用で、以下の事故が複数観測された。

| # | 事故 | 観測例 |
|---|------|--------|
| 1 | 曜日ずれ | 日曜日（2026-05-10）の朝投稿で「月曜の朝〜」と書いた |
| 2 | モチーフ乱用 | グミ・モンスター（エナジードリンク）の描写が短期間に連発、テンプレ化 |
| 3 | 時間軸の捏造 | 21時投稿で「夜22時にお風呂入れた」（未来時刻を過去形で記述）、「7:11に〜」のような分刻み時刻 |
| 4 | 締めが暗い | 大変さ・本音で終わる投稿が混じり、本人ブランド「仕事も子育ても好き／がむしゃらに楽しい」と乖離 |

根本原因: 現在のシステムプロンプトは

- 冒頭フックに「数字（朝5時／30分で／2000人超えて）」を **推奨** している（`momEntrepreneurGenerator.js:117`）
- 良い例3に「朝7時に起きて」と **時刻入りの模範文** が入っている（`momEntrepreneurGenerator.js:209`）
- 「今日が何曜日か」「この投稿がいつ出るか」をモデルに伝えていない
- 「直近どんなモチーフを使ったか」もモデルに伝えていない
- 「締めは明るく」ルールは memory にだけあって本番プロンプトに無い

つまり **本番プロンプト側にガードが一つも入っていない**。memory やこの会話で約束しても、コード側に反映されない限り効かない。

## 2. 方針

- **案A** を採用（プロンプト注入 + 既存の重複ガード拡張 + 生成後フィルタ）
- 既存の `post-now.js → generateMomEntrepreneurTweets → pickBest` フローに沿って、3つの層で防御する
  - **層1**: プロンプトに変数を注入（曜日／投稿スロット／禁止モチーフ／締めトーン）
  - **層2**: システムプロンプト本体の改修（時刻奨励文の削除、ハッピー締めルール追加）
  - **層3**: 生成後の機械検査（時刻・人数・売上の数字パターンを検出し違反候補を除外）

## 3. 設計詳細

### 3.1 プロンプト注入する変数

`post-now.js` で算出し、`generateMomEntrepreneurTweets()` の引数に追加して **user prompt** に埋め込む。system prompt は cache_control で固定し触らない方針だが、3.2 の本体改修は別途行う（一度きりの変更でキャッシュ再生成されて以降は再利用される）。

| 変数 | 値の例 | プロンプト内での使い方 |
|---|---|---|
| `todayJst` | `"2026-05-10（日曜日）"` | 「この投稿が出るのは ${todayJst} です。曜日を語るならこの曜日に合わせる。合わせないなら曜日を一切口にしない」 |
| `slotInfo` | `"夜21時（JST）"` または `"朝8時（JST）"` | 「この投稿は ${slotInfo} に投稿されます。投稿時刻より未来の時刻を本文に書かないこと」 |
| `bannedMotifs` | `["グミ", "モンスター"]`（空配列もありうる） | 「今回の投稿では次の単語を使わない: ...」（空なら丸ごと省略） |

JST 計算ロジック:

```js
function getJstTodayInfo() {
  const jst = new Date(Date.now() + 9 * 3600 * 1000);
  const y = jst.getUTCFullYear();
  const m = String(jst.getUTCMonth() + 1).padStart(2, '0');
  const d = String(jst.getUTCDate()).padStart(2, '0');
  const dows = ['日曜日', '月曜日', '火曜日', '水曜日', '木曜日', '金曜日', '土曜日'];
  const dow = dows[jst.getUTCDay()];
  return `${y}-${m}-${d}（${dow}）`;
}

const SLOT_LABELS = { morning: '朝8時（JST）', evening: '夜21時（JST）' };
```

### 3.2 システムプロンプト本体の改修

`src/services/momEntrepreneurGenerator.js` の `SYSTEM_PROMPT` 内、以下を編集する。

#### (a) 冒頭フックの「数字」例から時刻・人数を削除

- **Before** (`:117`):
  ```
  - **数字**: 「朝5時」「30分で」「2000人超えて思う」
  ```
- **After**:
  ```
  - **数字**: 「3つ気づいた」「2回連続で」（時刻・人数・売上の数字は禁止）
  ```

#### (b) 良い例3を時刻ゼロに差し替え

- **Before** (`:208-222`): `朝7時に起きて／娘の小学校の支度しながら／片手でLINE確認してる☕…`
- **After**: 時刻表現を含まない朝バタバタ描写。行動ベースで書く。

  ```
  ## 良い例3（日常リアル・絵文字4個）
  娘の支度を横目に
  片手でLINE返してる☕

  娘を送り出してから息子を起こして
  保育園の準備しながら
  もう今日のタスクが頭で回ってる😵‍💫

  バタバタの中で仕事の頭
  でもこの忙しさが好きなんだよね🥹

  同じ毎日のママいる？一緒にがんばろ💓

  #ORIMAMA
  ```

  - 「朝7時」「○時」を含まない
  - 締めは明るい肯定（「好きなんだよね」「一緒にがんばろ」）— 二重否定や中立で終わらせない

#### (c) 「やってはいけないこと」に時間軸ルールを追加

`:170` 付近のNGリストに以下を追加:

```
- 具体時刻（○時／○:○○／○時○○分）を本文に書く
- 「朝○時に起きる／起きた」など時刻起点の描写
- 人数の数字（2000人超えて／フォロワー◯人達成）
- 売上・金額の数字（月商◯万円／単価◯円）を本文に出す
- 時間軸を匂わせる数字（30分で／2時間かけて／1時間後に）
- 暗いトーン・諦め・愚痴・自虐で締めること
```

#### (d) 「投稿の質の基準」の冒頭に【最重要】締めルールを追加

```
## 【最重要】締めのトーン
**最後の1〜2行は必ず明るく前向きに終わる。例外なし。**
- 冒頭〜中盤で大変さ・本音・しんどさを出すのはOK
- ただし最後は必ず「光・好き・がんばれる・しあわせ」に着地させる
- ベースの世界観: 「仕事も子育ても好き／がむしゃらな毎日が楽しい」

### 締めのOK例
- だから今日もがんばれる💪✨
- この忙しさが好きなんだよね🥹
- 同じ人いる？一緒にがんばろ💓
- 明日も全部やるって決めた❤️‍🔥
- 結局これが私のしあわせかも🌸

### 締めのNG例
- 「疲れた」「限界」「辛い」「やめたい」で締める
- 「これでいいのかな…」のような迷い・不安で終わる
- 「誰にもわかってもらえない」のような孤独で終わる
- 自虐・卑下で終わる
```

#### (e) 「生成時の心構え」末尾に注意喚起を追加

```
- 時刻・人数・売上の数字は本文に書かない
- 締めは必ず明るく前向きに（最後の1〜2行）
- 投稿が出る日付・曜日・スロットは user prompt で渡される。それに従う
```

### 3.3 直近モチーフ検出ロジック

`post-now.js` に新規関数:

```js
const RATE_LIMITED_MOTIFS = ['グミ', 'モンスター'];

function detectBannedMotifs(tweets) {
  const cutoff = Date.now() - 30 * 24 * 3600 * 1000;
  const recent = tweets.filter(t => new Date(t.created_at).getTime() >= cutoff);
  return RATE_LIMITED_MOTIFS.filter(m =>
    recent.some(t => t.text.includes(m))
  );
}
```

- 直近30日に1度でも使われていれば、その単語を今回の禁止リストに入れる
- → 結果として **モチーフは最低30日空く** ＝ 実質「月1回程度、ここぞって時だけ」を保証
- 空配列なら user prompt 側で `bannedMotifs` ブロックを丸ごと省略

generator 側の受け取り（追加）:

```js
const motifBlock = bannedMotifs.length > 0
  ? `\n【今回の投稿で使わない単語（直近30日に使用済みのため）】\n${bannedMotifs.map(m => `- ${m}`).join('\n')}\n`
  : '';
```

### 3.4 生成後フィルタ強化（pickBest）

`post-now.js` の `pickBest` 内 `valid` 判定に時間軸チェックを追加。

```js
const TIME_AXIS_PATTERNS = [
  /\d{1,2}[:：]\d{2}/,                          // 7:11 / 21:00
  /\d{1,2}時(\d{1,2}分)?/,                      // 22時 / 7時11分（例外なし）
  /\d+\s*人(?!間|生|員|参|気)/,                 // 2000人（人間・人生・人員・人参・人気は除外）
  /(月商|売上|年商|単価|月収|月収入|年収)[^\s]*?\d/, // 月商500万
  /\d+\s*(分で|時間で|分かけて|時間かけて|分後|時間後)/, // 30分で / 1時間後
];

function violatesTimeAxis(text) {
  return TIME_AXIS_PATTERNS.some(p => p.test(text));
}
```

既存の `pickBest` の `valid` 判定に `&& !violatesTimeAxis(t.text)` を追加。違反候補は除外。**全候補が違反した場合** は、既存の avoidPhrases フォールバックと同じ思想で、警告ログ（`logger.warn(...)`）を出した上で、違反フィルタを通っていない `pool`（句読点・ハッシュタグ等の基本条件は満たす集合）から既存ロジック（195字に最も近いものを選ぶ）で1本採用する。リトライ生成はしない（コスト・レイテンシ回避）。

### 3.5 締めのハッピー化

機械検査での「明るさ」判定は精度が出ないため、**プロンプト指示と良い例による誘導** で固める方針（3.2 (d) と user prompt 追加指示）。違反検出ロジックは入れない。

user prompt の末尾指示に追加:

```
- **最後の1〜2行は必ず明るく前向きに着地させてください（最重要・例外なし）**
```

## 5. 検証手順

1. **手動生成で目視確認**: `node generate-tweets.js`（または同等の手動コマンド）で morning / evening 各5本ずつ計10本生成
   - 時刻表現（`7:11` `22時` `朝7時起き` 等）が一切出ないこと
   - 曜日に言及するなら 2026-05-10（日）と一致すること
   - グミ・モンスターが出ないこと（直近30日に存在するため禁止リストに入るはず）
   - 締めが必ず明るく前向きであること（暗い・諦め・愚痴で終わっていない）
2. **`violatesTimeAxis` 単体動作確認**: 違反サンプル文字列（`"22時に〜"` `"7:11に〜"` `"月商500万"` `"2000人"` `"30分で"`）を渡して true、安全サンプル（`"3つ気づいた"` `"2児の母"`）で false が返ることを確認
3. **本番反映後の確認**: `git push` 後、次の自動投稿（朝8時 or 夜21時）の本文をユーザーに目視で確認してもらう

## 7. リスクと対応

| リスク | 対応 |
|---|---|
| プロンプト改修後、モデルが過剰に防御的になり面白くない投稿ばかり出る | 検証手順1の手動生成で確認。問題あればプロンプト調整（NG列挙のトーンを和らげる等） |
| `violatesTimeAxis` の正規表現が誤検出（例: `"2児"`が`/\d+\s*人/` に当たる） | パターンに negative lookahead（`(?!間\|生\|員\|参\|気)`）を入れる。検証手順2で確認 |
| 「グミ・モンスター」を本人が本当に書きたい日に書けなくなる | 仕様通り（月1回程度＝最低30日空ける）。例外運用は手動投稿で対応 |
| キャッシュ済みの system prompt 改修 → 初回のみキャッシュ作成コスト | 一度きり。以降は通常通りキャッシュヒット |
