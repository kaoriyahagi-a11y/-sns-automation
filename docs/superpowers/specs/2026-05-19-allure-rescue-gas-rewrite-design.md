## Section 1. ゴールと境界

### 背景
会計担当者が引継ぎなしで離脱（2026年4月）。矢萩さん（株式会社ORI）が引き継ぎ、**翌月10日 月次締め**を絶対に落とせない緊急状況。Allureの新人スタッフ向け業務マニュアル v0.1 が発行済（領収書→「Allure経費」シート→TKC手入力という1件ずつ作業フロー）。

旧 v1 設計（2026-05-01）は Python + Document AI + Anthropic API のローカル実行ベースだったが、フィードバック `feedback_no_claude_dependency.md`（経理系はGAS+Sheetsで完結、Claude/AI運用依存禁止）と `feedback_no_copy_paste.md`（コピペ入力ゼロ、Drive直接接続）と整合しないため、本v2で全面書き直し。

### ゴール
矢萩さんが **Driveに領収書PDFを置くだけ** で、月初に **TKC FX2取込CSV** が降ってくる状態を作る。**6月10日（5月分の月次締め）** を初回稼働ターゲットに、Week 3で並走運用を立ち上げる。

### 達成条件
1. レシート（領収書）PDFがDriveに投入されたら、**人手のコピペ・アップロード操作なしで** 「Allure経費」シートに自動行追加される
2. シートの拡張は**完全に裏方**（`Allure経費` 9列構造は変えず、`_TKC出力` 別タブで関数ミラー＋マスタJOIN）
3. 矢萩さんがメニューから「TKC CSV出力」をクリックするだけで、`_TKC出力` 由来のCSVがDriveに保存される
4. 自動行のうちOCR/分類に不確実があるものは **要確認マーク**（H列セル背景=黄＋セルコメント） で表示される
5. **運用基盤に Claude/Anthropic API を一切組み込まない**（OCR=Document AI、分類=ルールベース、確認=人手）

### 想定の月次フロー（Before / After）
| Step | Before（マニュアルv0.1） | After（v2完了後） |
|---|---|---|
| 1 | スタッフがDriveに領収書を上げる | **同左** |
| 2 | 矢萩さんがレシートを1件ずつ「Allure経費」シートに手入力（4-6h） | **GASが自動行追加（0h）、要確認のみ目視（〜15min）** |
| 3 | 「Allure経費」を元にTKC仕訳を1件ずつ手入力（4-6h） | **メニュー「TKC CSV出力」→Driveに保存（〜5min）** |
| 4 | TKC側で月次試算表生成 | **同左** |

**月次工数: 8-12h → 約 30分** が目安（**C1ルートに限った推定**、大型支払・仕入請求書は別途継続）。

### スコープ外（v1ではやらない）
- ❌ **C2 大型支払の自動分類**（通帳・カード明細パース）→ 矢萩さん継続手入力。v2以降で検討
- ❌ **C3 仕入請求書OCR**（6社）→ 同上、v2以降
- ❌ **Claude/Anthropic API の運用組み込み**（feedback違反）→ 半永続的に禁止
- ❌ **給与計算自動化** → 別案件（`allure-payroll/` 並走中）
- ❌ **海旬・Primeへの横展開** → Phase 2/3

### 制約
- 「Allure経費」シートの**既存9列構造は維持**（マニュアルv0.1の新人向け運用を壊さない）
- TKC FX2 CSV取込仕様は **Phase 0 で要確認**（部門コード一部はあり、ヘッダ・サンプル未取得）
- 既存`receipt-ocr/`（Python製）には **手を入れない**（株式会社ORI稼働中のため）
- GAS実行時間制限（1実行6分）と日次呼び出し回数制限（無償版でも基本問題なし、後述）に収まる設計

### 対象組織
- **Allureグループ 6店舗**: Allure ／ FONS ／ IVY ／ ICY ／ NI ／ Fivent（duftは2026-04開始の新店舗、v1では含めず）

### 2-3. 設計原則
1. **シート9列のマニュアル互換を絶対維持**：新人スタッフが見たときの体験を変えない
2. **`_TKC出力` は純関数ミラー**：人手で `Allure経費` を編集しても即時追従、同期ズレなし
3. **OCR/分類の不確実は隠さず明示**：要確認はH列背景色＋コメントで一目瞭然
4. **Claude/AI に運用依存しない**：分類はすべてルールベース＋人手フォールバック、LLMはv1で未使用
5. **重複検知は決定論**：`日付＋金額＋支払先` の3項目一致で既存行扱い、新行作成しない
6. **TKC CSVは差し替え前提**：Phase 0で仕様確定後、`tkcExporter.gs` の1関数差し替えで対応

## Section 3. データモデル

### 3-1. 「Allure経費」シート（既存・変更なし）
マニュアルv0.1記載の通り：

| 列 | 項目 | 入力ソース（GAS処理時） |
|---|---|---|
| A | NO | 行番号自動採番 |
| B | 収日（使用日付） | DocAI抽出 |
| C | 支払先 | DocAI抽出 |
| D | 勘定科目 | `_科目マスタ` 部分一致、もしくは空欄→要確認 |
| E | 合計金額 | DocAI抽出 |
| F | 使用者 | ファイル名から抽出（戸田／NI／IVY／ICY／FONS／Allure） |
| G | リンク | DriveファイルURL |
| H | TKC | FALSE（=未取込） |
| I | 備考 | 自由欄、必要に応じてGASが「OCR要確認」等を書く |

**人手編集ルール**: 矢萩さんは自由にこのシートを編集できる。GASは**追記のみ・既存行は触らない**（重複検知で重複は作らない）。

### 3-2. `_TKC出力` タブ（新規・関数ミラー）

A2セルに以下のような ARRAYFORMULA を1本：
```
=ARRAYFORMULA(IFERROR(
  {
    Allure経費!A2:A,                                          // 元行番号
    Allure経費!B2:B,                                          // 仕訳日付
    VLOOKUP(Allure経費!D2:D, _科目マスタ!A:C, 2, FALSE),       // 借方科目コード
    VLOOKUP(Allure経費!F2:F, _使用者マスタ!A:C, 3, FALSE),     // 部門コード
    VLOOKUP(Allure経費!D2:D, _科目マスタ!A:C, 3, FALSE),       // 税区分コード
    Allure経費!E2:E,                                          // 借方金額
    "1110",                                                   // 貸方科目コード = 現金固定
    Allure経費!E2:E,                                          // 貸方金額
    Allure経費!C2:C & "／" & Allure経費!F2:F,                  // 摘要
    REGEXEXTRACT(Allure経費!G2:G, "[^/]+$")                   // 証憑番号（リンクからファイル名抽出）
  }, ""))
```
（実装詳細はwriting-plansで詰める。上記は要素表示用）

各列：
| 列 | 内容 | 由来 |
|---|---|---|
| A | 元行番号 | Allure経費!A |
| B | 仕訳日付 | Allure経費!B |
| C | 借方科目コード | _科目マスタ JOIN |
| D | 借方部門コード | _使用者マスタ JOIN |
| E | 借方税区分 | _科目マスタ JOIN |
| F | 借方金額 | Allure経費!E |
| G | 貸方科目コード | "1110"（現金）固定、v2で借方変更可 |
| H | 貸方金額 | Allure経費!E |
| I | 摘要 | 支払先＋使用者 |
| J | 証憑番号 | リンクのファイル名 |
| K | TKC | =Allure経費!H |
| L | 要確認 | =背景色判定 or _要確認マーカー |

Phase 0で確定後、列順・コード体系を `tkcExporter.gs` で吸収。

| TKC=TRUEは変更不可 | TKC取込済み行はGASからの編集禁止（誤再取込防止） |

### 4-3. 要確認UX
矢萩さんの目視作業は、H列が黄色の行を上から見ていくだけ：

```
| NO | 収日 | 支払先 | 勘定科目 | 金額 | 使用者 | リンク | TKC | 備考  |
```

### 4-4. TKC CSV出力フロー
1. 矢萩さんが「Allure経費」シートのメニュー「経理自動化」→「TKC CSV出力」をクリック
2. GAS `exportTkcCsv()` が起動：
   - `_TKC出力` から TKC=FALSE & 要確認=FALSE の行を抽出
   - CSVバイト列を組成（仮スキーマでスタート、Phase 0確定後に列順調整）
   - DriveのCSVフォルダに `TKC仕訳_2026-05_YYYYMMDDhhmmss.csv` で保存
   - Gmail通知：「CSVファイル: {Drive URL}、N行出力」
3. 矢萩さんがCSVをダウンロードしてTKC FX2にアップロード
4. TKC取込成功した行を、矢萩さんがシート上で H列=TRUE に一括更新（GASメニュー「TKC取込済みマーク」で範囲指定一括可）

### 4-5. 失敗時のフォールバック
| 失敗パターン | フォールバック |
|---|---|
| DocAI 完全失敗（PDF壊れ等） | 行作成せず、`_OCRログ` に記録、Gmail即時通知 |
| DocAI 部分失敗（金額のみ読めない等） | 行は作る、欠損列空欄＋要確認=TRUE |
| 使用者抽出失敗 | F列=「不明」、要確認=TRUE |
| 部門推定失敗 | F列の値が `_使用者マスタ` にない→要確認、`_使用者マスタ` に追加して再実行 |
| 科目推定失敗 | D列空欄＋要確認、`_科目マスタ` に追加して再実行 |
| 重複行 | 新行作らず、`_OCRログ` に「重複」記録 |
| GAS 6分超過 | バッチサイズを小さくして翌トリガに繰り越し（処理済みフラグで判定） |
| DocAI APIキー失効/レート制限 | リトライ3回→失敗ログ＋Gmail即時通知 |
| CSV出力時に必須欄空 | 該当行リストをポップアップ表示、出力中断 |
| TKC取込時のエラー | TKC側のメッセージを矢萩さんが見て、シートを手修正→再エクスポート |
