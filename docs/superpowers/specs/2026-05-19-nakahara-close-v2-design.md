## 1. 背景と目的

### 1.1 現状

`/nakahara-close --month YYMM` は以下まで実装済:
- Drive 仕入PDF → OCR
- 請求書作成一覧 SS の月次タブから売上scan
- 仕入差異算出 (OCR vs 請求書)
- 入出金管理表 SS の `2026年{M}月分_試作v34` シート生成 (税込合計のみ)

### 1.2 課題

試作v34 シートは「税込合計」しか持たず、矢萩さんが MFクラウド会計 へ仕訳入力する作業が完全手動。1月あたり 100件超の仕訳手打ちが発生。

### 1.3 v2 のゴール

矢萩さんの仕訳入力作業を「**仕訳案レビュー (確定/保留/却下 を選ぶ) + MF取込CSV をMFにアップロード**」の2ステップに圧縮する。コピー&ペースト入力をゼロにする。

### 1.4 スコープ外 (v2 対象外)

- 請求書作成一覧 SS と 入出金管理表 SS の物理統合 (別タスク、将来検討)
- Apps Script への移行 (将来の SaaS化 phase で再検討)
- 期首振替・決算整理・減価償却仕訳の自動生成 (月次の入出金実取引のみが対象)
- 給与・社会保険・立替経費の仕訳 (役員立替 `_ 店名 _` パターンは別フロー)
- インボイス番号管理 (中原は現状未使用)

## 3. 試作v34 シートの改修 (Phase 2)

### 3.1 追加カラム (各セクション共通、既存L列の右に追加)

| 列 | 名前 | 取得元 | 用途 |
|---|---|---|---|
| M | 8%対象(税込) | PDF税率別合計 (OCR) | 仕訳案生成入力 |
| N | 10%対象(税込) | PDF税率別合計 (OCR) | 仕訳案生成入力 |
| O | 8%税額 | `=ROUND(M/1.08*0.08)` 数式 | 検算用 |
| P | 10%税額 | `=ROUND(N/1.1*0.1)` 数式 | 検算用 |
| Q | 検算 | `=IF(M+N=L,"OK","NG:"&(L-M-N))` | M+N と L (確定額) の整合チェック |

### 3.2 改修内容

1. `ocr_purchase_pdfs.py`:
   - pdfplumber の出力から「8%対象¥X / 10%対象¥Y」表記を正規表現で抽出
   - `purchase_pdf_extracted_20{YYMM}.json` のスキーマに `subtotal_8`, `subtotal_10` フィールド追加
2. `build_nakahara_shisaku_v34_202603.py`:
   - 仕入セクション/その他フォルダセクションで、各行に M/N 列を埋める
   - O/P/Q 列は数式リテラルとして埋め込み
   - 売上セクション (15〆/末〆) は税率取得元が異なるため、暫定はマッピング辞書側で取引先別税率を引く (PDF 抽出は仕入を優先)

### 3.3 手修正運用

- 矢萩さんが J列「手修正(税込)」を入力した場合、L = 手修正値となり M+N と乖離可能 → Q列「NG」表示
- 解決: J列入力時は M/N も合わせて手入力する運用 (Apps Script トリガによる自動補正は将来検討)

### 3.4 PDF に税率別合計が無い特殊請求書

固定費・家賃・保険料など、税率別表記の無い PDF は:
1. マッピング辞書から取引先別の標準税率を引く
2. 例: `クリプトメリア (家賃)` → 常に10% → M=0, N=L
3. 該当取引先が辞書に無ければ M=0/N=0 で残し、O列「未登録」で矢萩さんレビュー

## 4. マッピング辞書の学習 (Phase 6 の前段)

### 4.1 入力

Drive `経理データ_中原水産/MF仕訳エクスポート/` 配下の MF仕訳帳CSV (Shift_JIS, 19列)。
矢萩さんが MFクラウドから月次でエクスポートしてアップロード。

### 4.2 学習スクリプト `build_partner_mapping.py`

1. 全CSVを `encoding='cp932'` で読込
2. 取引No 単位でグルーピング (複合仕訳の複数行を1取引として再構築)
3. 期首振替 (取引No=1) と決算整理 (取引日=12/31) を除外
4. **補助科目** (= 取引先) ごとに `(借方勘定科目, 借方税区分, 貸方勘定科目, 貸方税区分)` の出現頻度をカウント
5. 最頻パターンを「標準」として辞書化、信頼度を付与
6. 出力: `.work/partner_mapping_中原.json`

### 4.3 辞書スキーマ

```json
{
  "オーシャンジャパン株式会社": {
    "type": "仕入",
    "debit_account": "仕入高【8％】",
    "debit_tax": "課税仕入 (軽)8%",
    "credit_account": "買掛金",
    "credit_tax": "対象外",
    "summary_template": "{partner} {month}月分",
    "confidence": "高",
    "occurrences": 9
  },
  "築地魚市場株式会社 / 10％": {
    "type": "売上",
    "debit_account": "売掛金",
    "debit_tax": "対象外",
    "credit_account": "売上高【10％】",
    "credit_tax": "課税売上 10%",
    "summary_template": "{partner} {month}月分",
    "confidence": "高",
    "occurrences": 22
  }
}
```

### 4.4 信頼度ラベル

- `高` : 出現回数 ≥ 10
- `中` : 出現回数 3-9
- `低` : 出現回数 1-2
- `未登録` : 0 (辞書に無し)

### 4.5 上書きマスタシート `_仕訳マッピング_中原`

入出金管理表 SS 内の新タブ。

| 列 | 名前 | 用途 |
|---|---|---|
| A | 取引先名 | 補助科目の値そのまま (例: `築地魚市場株式会社 / 10％`) |
| B | 種別 | 仕入 / 売上 / 固定費 / 立替 / 振替 |
| C | 借方勘定科目 | |
| D | 借方税区分 | |
| E | 貸方勘定科目 | |
| F | 貸方税区分 | |
| G | 摘要テンプレ | `{partner} {month}月分` 等 |
| H | 信頼度 | 自動学習結果 (高/中/低/未登録) |
| I | 出現回数 | 過去CSVでの件数 |
| J | ロック | ✓ を入れると過去CSV再学習時に上書きされない |

### 4.6 仕訳案生成時の優先順位

1. **ロック行 (J列✓)** → 最優先
2. **自動学習辞書** (信頼度 高/中) → デフォルト
3. **信頼度 低/未登録** → 種別推測 + デフォルト推奨値、O列「要確認/未登録」表示

### 4.7 未登録取引先の処理

- 取引種別を試作v34 のセクションから推測:
  - 仕入セクション → `"仕入"` → デフォルト `仕入高【10％】/課税仕入 10%/買掛金/対象外`
  - 売上15〆 → `"売上"` → デフォルト `売掛金/対象外/売上高【10％】/課税売上 10%`
  - 売上末〆 → 同上
  - その他フォルダ → `"固定費"` → デフォルト `支払手数料/課税仕入 10%/普通預金/対象外`
- 矢萩さんが手動で E-K 列を修正 → A列「確定」
- 次回学習時にマスタシート末尾に新規パターン候補として追加

## 5. 仕訳案タブ `仕訳案_YY.M月` (Phase 6)

### 5.1 生成スクリプト `build_journal_proposals.py`

1. 試作v34 シートを読込 (各セクションの行)
2. 取引先名を補助科目正規化 (中原慣習: `築地魚市場株式会社 / 10％` のような税率併記をそのまま保持)
3. マッピング辞書 + ロック行から推奨仕訳を引く
4. 18列の行データを生成
5. 入出金管理表 SS の `仕訳案_YY.M月` タブに上書き出力 (既存タブあれば clear→write)

### 5.2 列構成 (18列)

| 列 | 名前 | 自動/手動 | 内容・取得元 |
|---|---|---|---|
| A | 確定状態 | 手動 (プルダウン) | `確定` / `保留` / `却下` / 空 |
| B | 取引日 | 自動 | 試作v34 振込日(支払) or 入金予定日(入金) |
| C | 取引種別 | 自動 | `仕入` / `売上` / `固定費` / `立替` / `振替` |
| D | 取引先 | 自動 | 試作v34 取引先名 |
| E | 借方勘定科目 | 自動 (上書可) | マッピング辞書から推奨値 |
| F | 借方補助科目 | 自動 (上書可) | 中原慣習で取引先名 |
| G | 借方税区分 | 自動 (上書可) | マッピング辞書 |
| H | 借方金額 | 自動 | 試作v34 L列 (税込合計) |
| I | 貸方勘定科目 | 自動 (上書可) | マッピング辞書 |
| J | 貸方補助科目 | 自動 (上書可) | 取引先名 |
| K | 貸方税区分 | 自動 (上書可) | 通常 `対象外` |
| L | 貸方金額 | 自動 | 借方金額と同額 |
| M | 摘要 | 自動 (上書可) | テンプレ展開 |
| N | ソースPDFリンク | 自動 | 試作v34 G/H列リンクを継承 |
| O | マッピング判定 | 自動 | `OK` / `要確認` / `未登録` |
| P | レビューメモ | 手動 | 矢萩さん自由記述 |
| Q | 8%対象(内訳) | 自動 | 試作v34 M列 |
| R | 10%対象(内訳) | 自動 | 試作v34 N列 |

### 5.3 視覚補助

- A列にプルダウン `確定 / 保留 / 却下` 設定
- O列に条件付き書式:
  - `OK` → 薄緑
  - `要確認` → 薄黄
  - `未登録` → 薄赤
- Q/R 列両方 > 0 (税率混在) → 行全体に薄青の縞模様

### 5.4 冪等性

- 同月で複数回 `/nakahara-close --month YYMM` を実行可能
- 既存タブの A列「確定/保留/却下」と P列「レビューメモ」は保持される (再生成時に value preserve)
- 試作v34 の値変更 (J列手修正など) があれば仕訳案タブも再計算される (E-K 列が辞書由来の場合のみ更新、矢萩さんが上書きした E-K 値は保護)

## 6. MF取込CSV出力 (Phase 7)

### 6.1 出力スクリプト `export_mf_csv.py`

実行: `/nakahara-close --month YYMM --export-mf`

1. 仕訳案タブの A列が `確定` の行のみ抽出
2. MF標準19列CSVを生成 (Shift_JIS, 全フィールドダブルクオート囲み)
3. Drive `経理データ_中原水産/MF取込CSV/MF取込_中原_YY.M月_YYYYMMDD-HHMM.csv` に保存
4. 入出金管理表 SS の `MF取込_YY.M月` タブを上書き生成 (CSV と同じ19列 + 末尾にダウンロードリンク行)

### 6.2 CSV 仕様

- 文字コード: **Shift_JIS (CP932)**
- 区切り: カンマ、全フィールドダブルクオート囲み
- 改行: CRLF
- 列構成 (19列): `取引No, 取引日, 借方勘定科目, 借方補助科目, 借方部門, 借方取引先, 借方税区分, 借方インボイス, 借方金額(円), 貸方勘定科目, 貸方補助科目, 貸方部門, 貸方取引先, 貸方税区分, 貸方インボイス, 貸方金額(円), 摘要, タグ, メモ`
- 部門 / 取引先 / インボイス / タグ / メモ → 全空 (中原は未使用)

### 6.3 1取引 → CSV 行数展開

| 仕訳案タブの状態 | CSV出力行数 | パターン |
|---|---|---|
| 単一税率 (Q=0 or R=0) | **1行** | 借方 + 貸方が同じ行 |
| 税率混在 (Q>0 & R>0) | **3行** (取引No共有) | 行1: 借方=仕入高【8％】 Q円<br>行2: 借方=仕入高【10％】 R円<br>行3: 貸方=買掛金 (Q+R)円 |

### 6.4 取引No 付番

- 当月内の連番 (1, 2, 3, ...)
- 税率混在の3行は同じ取引No を共有 (MF が1複合仕訳として認識)
- MF 側で取込時に再採番されるため、衝突回避できれば任意値でOK

### 6.5 SS タブ `MF取込_YY.M月`

- CSV と同じ19列を並べる (Shift_JIS だが、SS は内部UTF-8 のため表示は問題なし)
- 最終行に `=HYPERLINK("<drive_url>", "📥 CSVダウンロード")` を埋め込み

## 7. エラー処理 (横断的)

| 段階 | 想定エラー | 対応 |
|---|---|---|
| OCR (Phase 1b) | 税率別合計の抽出失敗 (画像PDF等) | M/N=0 で書込 → 仕訳案O列「未登録」→ 矢萩さん手動補正 |
| 試作v34 → 仕訳案 (Phase 6) | Q列「検算NG」 | 仕訳案タブに `要確認` フラグ付き生成、A列初期値=保留 |
| マッピング辞書 (Phase 6) | 取引先が辞書に無い | O列「未登録」+ 種別推測でデフォルト値 |
| 確定 → CSV (Phase 7) | 借方合計 ≠ 貸方合計 | CSV から除外 + 警告ログ |
| 確定 → CSV (Phase 7) | E/G/I/K のいずれかが空 | CSV から除外 + 「要修正」ログ |
| OAuth (全Phase) | tokens.json 失効 | `auth_init.py` 再実行で復旧 |
| 月初実行 (Phase 1a) | Drive 月フォルダが存在しない | `WARN: month 2605 folder not configured` → 矢萩さんがフォルダ作成後に再実行 |

すべて **fail-soft**: 1行エラーで全体停止しない。エラー行は仕訳案タブに「要確認」状態で残し、矢萩さんがレビューで対処。
